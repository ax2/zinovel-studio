## 存储和请求边界

每书生成阶段：全书方案（总纲、分卷、世界/风格、主角与可增人物、主支线/伏笔、图像制作登记）、每卷完整结构化章纲/场景细纲、每章实际试写及章后状态、试写后当前状态与AI自检。宿主将结构化细纲渲染为可编辑Markdown，发布旁车由已核对卷章生成，不能靠空模板凑齐。

单独私有novel-batches目录使用同一队列/恢复事务实现job、冻结请求与结果登记；不另开书库写入内核。发送前持久化UUID，由官方任务账本沿用此UUID，预算未知也不退回预留。取消等当前请求落到终态，正常退出停止批次；重启只核对已有结果、保留unknown，不自动调用模型。

整本所需阶段都完整后，才通过当前桌面的唯一NovelStore提交为待审新书。提前分配book UUID，初始正文/全部规划卷（含无试写正文的卷）/创作资产/生成回执在同一可恢复事务落盘。相同身份和回执的重复提交只返回当前作品；已有其他作品或回执冲突拒绝覆盖。内容hash、批次、模型服务及实际请求UUID保留在书内；不含Key。
