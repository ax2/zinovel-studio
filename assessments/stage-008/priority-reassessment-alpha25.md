# alpha.25后的优先级与证据缺口

2026-10-24。本次已完成带图冻结/HTML源码、实际安装和升级增量，预览发行仍待完整门禁。对完整矩阵复查，尚有22项P0未verified；不按新增格式数量判断核心平台完成程度。当前正式状态26/40/40，不重新缩小106项目标。

下一切片优先核心写作保障：LIB-08跨书上下文隔离、OPS-06工具权限、OPS-07离线写作及OPS-05本地版本/独立备份。已有官方Harness工具白名单、手写/保存/阅读、完整目录备份恢复等真实实现；planned或部分测试不能直接等同完整验收，需要对照product-spec、data-model和architecture逐项核对。

1. 离线：配置明确不可达模型并使作者窗口网络请求失败，实际手写/自动保存/撤销/重启/阅读仍工作；监测是否有后台必需网络。模型故障只影响生成，不把Chromium网络拦截扩大成CLI全部断网或整台电脑飞行模式。不得中断用户其他网络应用。
2. 隔离/权限：两本带独立“秘密标记”的合成小说、资料与候选，通过真实Harness工具调用和宿主接口尝试跨书访问/提案；默认上下文只含显式当前书，拒绝越权必须在正式写前，不能只隐藏UI或依赖提示词。注入资料不能授予额外工具。
3. 备份：先区分同卷历史与独立副本。已读Windows分区元数据：D为Disk1/Partition2、E为Disk1/Partition3，二者是同一物理盘；C为Disk0/Partition3。后续合成异盘实测用D书库→C专用临时备份，记录真实卷/物理盘映射，不将不同盘符冒称独立物理盘。备份不含模型Key/应用任务，UI必须说明范围。
4. 路径与完整性：核对现有createBackup目的地按resolve做相对判断，对Junction等别名还需canonical realpath校验，避免“别名目的地在原书内”漏判；必须用合成目录先复现。恢复拒绝损坏hash/链接/未来schema并新建书，保留原书和备份。
5. 增量：data-model提出完整目录增量复制，现有v1为每次新建完整目录副本，不能据其声称增量已经实现。设计有版本的完整逻辑清单/不可变数据存储或其他可验证方案，明确中断恢复、原始v1兼容、容量预检和可搬移性；不能为容易通过测试而删除该要求。每个备份仍需完整可恢复的文件范围，不只复制最近改稿。
6. 持续诊断与真实输入法：日志不带真实正文/凭据；原生中文IME仍无已验证证据，insertText或模拟composition事件不是系统IME通过。保持未完成标记，后续专项实施。
