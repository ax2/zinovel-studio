# 结构化创作资料实施前复评（2026-10-23）

Stage-003 已有可靠单候选、局部接受、预算、恢复和审阅草稿的切片；多候选比较、另存小说分支和真实云模型文学质量未完成。21 个技能源不能代替创意、纲要、人物等实体的存储和管理。下一条独立开发线应先补手工可用的创作资料，再开放 Agent 提案工具；不以一次模型输出当实体系统完成。

## 最小完整纵向切片

先覆盖人物、地点/世界规则、总纲/卷纲/细纲、主支线、伏笔、创意记录。每类有明确类型和可选模板，同一实体有 UUID、schemaVersion、revision、title、notes、typed fields、status、chapter references 与 updatedAt；编辑界面允许手工修改、搜索、软删除恢复、历史核对和导出。不要用一个任意 JSON 文本框冒充不同创作领域的编辑器。

人物信息分“作者设想”和正文已证实状态；人物关系和认知变化不是覆盖最后一张卡。伏笔的计划、实际埋设、回收分别表示，后两者须绑定正文锚点及 hash。大纲与真实章节通过稳定 ID 引用，不靠标题或第几章字符串推断。新增角色改名只更新卡片及别名，正文替换必须独立预览确认。

优先用作品目录中的独立 JSON 记录结构和 Markdown notes 字符串，复用现有原子日志/版本和冲突规则。当前 NovelStore 集中管理路径、单实例串行队列和事务；增加实体服务前先提炼可复用存储内核，不能在新服务另造不共享的队列导致两服务互相覆盖。SQLite 仍是未来派生索引，不新增第二个主数据来源。

## 备份和身份边界发现

现有 createBackup 递归复制整部书目录（拒绝链接），新卡片放在书内可自然进入清单；restoreBackup 校验全部文件后分配新 book ID。卡片应尽量使用书内相对实体 ID，避免处处冗余 bookId；需要跨书引用时明确外部关系，并在恢复报告中处理。

当前 AI 任务与审阅草稿位于应用数据 tasks/，不在书目录备份中。整书备份可以恢复正文/书内历史/标记，但**不能**声称能迁移应用任务和审阅草稿；接下来需另做工作区备份或按书导出任务包、重新绑定身份的只读导入。新书 ID 下不得自动接收旧书候选或据旧接受回执重放写入。已有版本的整书备份不因此改变含义，发行说明需列明这个实际范围。

## 验收顺序

1. 独立合成新书手工创建各类材料，重启、修改冲突、软删除恢复、书备份恢复后核对引用和原始内容。
2. 界面查看浅/深色、大/窄窗、键盘、搜索分页和明确状态。资料抽屉与正文同屏，避免作者在弹窗中丢失上下文。
3. 官方 Harness 只读上下文工具返回实际选中资料及版本，提案工具只能生成待确认变更；作者接受后通过同一实体服务写入。
4. 用“创意→试写→选版→总纲→人物→细纲→正文”合成案例做完整往返，再标对应功能验收。地图、定妆和发布留在后续独立阶段，不能用素材占位宣称完成。
