# alpha.30 独立模型配置后端

源码后端8项专项与完整267项/类型/规划通过。OPS-01由planned到in-progress，106项现26 verified/46 in-progress/34 planned；没有宿主、作者管理界面或新配置的真实Harness/图像调用证据，没有本版安装资格，不升级整项验收。

ModelProfiles独立于书库，沿用应用唯一写入者原则，内部串行并复用Windows无共享原生句柄锁。模型配置文件有格式/版本、修订、原始磁盘hash、独立profile ID和文字/图像路由。每配置有自己的密文/完整service scope/协议/预算；公开视图显式挑字段，不回读密文/Key。首次迁移以flush后create-only link公布，不覆盖已有文件；后续存储在加密后复核原始hash再原子替换。后提交清理或锁释放异常保留已提交事实。

8项真实文件系统专项：

- 旧密文迁移到默认文字profile，不修改调用方旧记录；新增文字B不改变A的活动选择，明确切换后只解密B；新建无Key配置不继承任何Key，旧修订拒绝。
- 图像有独立Key/预算/选择，不能放进文字路由；适配器尚未接入时runnable=false，resolve在解密前拒绝，不借文字Key。价格未知是null，不当0；启用金额阈值需作者明确配置单价。
- 改服务不输入新Key清旧密文；替换明确新Key；变能力类型须新建配置；活动配置删除前须明确换/取消选择；文字图像预算不得混用。
- 相同revision但磁盘外部编辑也拒绝旧保存；未来schema/坏UTF8字节保留且不重置。加密期间外部编辑拒绝覆盖；加密不可用不回退明文。
- 两个实际服务实例争用同文件，一个持有原生锁时另一个拒绝；重复迁移、配置路径符号链接拒绝，原字节保持。
- 名称冲突、隐藏cipher字段、未填图像模型、无单价费用阈值拒绝；20配置和2MiB文件边界保护，不因超限清空或重写原数据。

单元测试crypto适配为显式合成codec，**不是OS安全存储加密认证**。当前29旧设置服务仍是唯一实际桌面入口；新profile类未接入正文任务，不把存储返回的文字runnable标识当新路由已集成。下一步需真实DPAPI adapter、作者明确迁移/管理、生成前核对所见配置、官方Harness两服务Key隔离/重启/升级、再实现图像生成候选完整生命周期。完整设计要求保留于design/model-profiles-and-capabilities.md。
