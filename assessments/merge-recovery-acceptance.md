# EDIT-08：冲突保留与三方合并

2026-10-22，Windows / Electron 44.7.0。18 项基础测试及真实桌面专项通过。

## 实测行为

`tests/merge.test.mjs` 验证共同基线上的不相交修改组合、重叠修改保守交由作者、Unicode 代理对完整、共同基线缺失时不伪造自动合并。`scripts/smoke-merge.mjs` 操作真实窗口：

1. 应用修改首段、外部修改末段；三栏显示基线/磁盘/当前，生成同时保留两侧的合并候选。确认前磁盘不变，接受后字节准确；一次撤销恢复作者的合并前编辑。
2. 同一末尾发生两次追加时提示相交，作者决定内容。对话框打开后再外改，旧确认被拦截；重新读取磁盘后才能接受。
3. 接受任意一侧前，基线、当前稿、磁盘稿持久化到独立冲突记录并加入历史。接受磁盘后，可从历史恢复尚未正式保存过的当前稿。
4. 弹窗内 Ctrl+S 不触发背景正文保存；Tab/Shift+Tab 保持在弹窗，Escape 关闭普通弹窗后恢复触发按钮焦点。冲突弹窗需完成明确选择。

截图 [三方合并](../screenshots/stage-002/merge/three-way.png) 已查看：宽窗 1426×923 CSS 像素、DPR 1.25、浅色，三栏与编辑区可读。完整 [运行回执](../screenshots/stage-002/merge/merge-smoke.json)。

## 保守边界

当前自动合并每一侧采用一个连续变化跨度；一侧存在多个远隔修改时会保守合成较大跨度，因此可能要求额外人工处理，不会将不确定的重叠自动覆盖。编辑框始终可手改，无冲突标记串混入正文。旧恢复缓存若没有共同基线，明确显示缺失。

文件系统无法阻止外部编辑器在最终比较与 rename 之间写入；现有版本/hash 检测与恢复事务不构成外部进程锁。跨进程书库租约、同步盘语义和磁盘满仍待验收。键盘边界测试不是完整屏幕阅读器认证。
