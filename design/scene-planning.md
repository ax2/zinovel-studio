# 场景规划共享视图（alpha.8 开发切片）

目标：把已有 scene 资料变成可安排到章节的场景看板，章纲视图读取相同顺序。正文文件不会因为移动规划卡片而重排或被自动拼接。

## 主数据与兼容

场景内容继续来自 materials/<id>.json，不复制目标/阻碍/选择/结果字段。书内 planning.json 保存 schemaVersion、revision 和 placements：每个 sceneId 至多一条，包含所属 chapterId（null 表示未安排）与显示顺序。已有 scene 的多章引用仍是参考关系，不偷换为主要归属；看板首次明确安排后才产生 placement。

未安排、有效章节、已删除/缺失章节必须分别显示，不把失联场景静默丢掉。章标题变化只改显示；卷章重排使用现有 orderedChapters 作为列顺序。卡片软删除后保留位置记录，恢复不重新编号。旧程序可以忽略 planning.json，不承诺完整降级编辑兼容。

## 修改约束

每次移动提交场景 ID、目标章、相邻场景 ID 与 planning 的 revision/hash；宿主核对场景在本书且未删除、目标章有效、相邻卡确实属于目标列。在共享 BookStorageKernel 内恢复并执行单次 planning 事务；旧规划保留历史。移动操作不接受模型提供的文件路径。

开始时把现有 scene（含软删除）逐项纳入视图，JSON 损坏以可见错误计数报告。看板/章纲从相同快照派生；显示“尚未写入正文”，避免把规划位置当作段落证据。章纲可读取对应 scene 的有序字段，作者原章纲文本保留。alpha.8未包含侧边场景节点；alpha.36开始接入下述树。

首次移动把扫描到的所有场景身份纳入位置表；未安排的新场景按 ID 确定顺序，已安排项按 order 排序。移动按目标相邻 ID 插入并重新编号，删除/失联项保留。扫描共享每批 32 条的有限读锁，正文保存可以在批次之间执行；快照可能跨资料版本，写入时重新验证实际移动/相邻场景和最新章节。没有建立全文索引，也未声称超大看板已经过低端设备验收。

## 交互与验证

提供章节列、未安排列、可点击的场景卡和显式“移动到章节/上移/下移”控件；拖拽是同一操作的快捷入口。窄窗提供单列选择与列表，不能依赖横向拖拽才能使用。打开场景复用语义资料编辑，正文入口使用准确章节 ID。

验证应包括：实际鼠标拖拽、键盘移动、跨卷顺序、重启保持、删除恢复、外部 CAS 冲突、丢失引用可见、备份恢复及正文原始字节不变。看板不能仅凭静态卡片截图标完成。

已完成的源代码与真实桌面验证见 assessments/stage-004/scene-planning-acceptance.md。界面字段仅摘要前 240 字符，完整编辑复用原资料卡，避免双份字段漂移。历史文件保存于 .zinovel/planning-history，历史恢复界面尚未提供；当前不生成规划正文或把移动当作正文事实。

## alpha.36 卷章树

读取同一planning快照和稳定场景ID，章内分支20项分页，标题检索保留所属章。未安排与失联项分组，显示其他章节状态时明确提示去“全部章节”查看。不可读场景禁用，已回收资料可显式恢复原位置。树只导航，实际重排仍进同一看板；尚无树内拖拽或内联创建。

树接收本书资料/卷章变化和独立规划事件，120ms合并，单读取在途及一次待刷新；规划移动不会触发无关AI参考选择重查，正文键入不扫描。当前章在快照后到达也能展开，手工折叠保留到下一次选章。新导航先保存正文并尊重资料/形象关闭保护；资料缓存失败仍能明确正式保存或放弃当前资料，不能绕过其他编辑器保护。源码证据见assessments/stage-002/scene-tree-source/README.md，安装、性能与未知缓存格式范围仍待。
