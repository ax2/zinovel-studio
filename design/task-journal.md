# Stage-003 任务与候选恢复设计

状态：待实现；2026-10-22 在安装测试期间审查现有 runtime 后制定。不是运行时完成记录。

## 问题

现有任务只记录技能、模型和最终候选，窗口内可以审阅，但重启后没有入口找回。记录未绑定书/章/选区基线，不能安全地在重启后直接重新应用。并发检查也在异步准备之后才占位，两次极近的请求存在同时进入的机会。

## 文件与状态

继续使用应用私有 tasks/<UUID>/ 目录；task.json 是有 schemaVersion 的轻量索引，snapshot.json 保存冻结的书/章 ID、完整编辑缓冲、存盘基线 hash、UTF-16 范围、技能版本和上下文来源，proposal.json 保存候选。用同目录原子写入，路径拒绝链接和越界；列表不加载全部正文。

准备阶段立即占用单任务槽位。状态为 preparing → running → awaiting-review → applied；旁支 cancelled/failed/interrupted/discarded。启动时把遗留 preparing/running 标 interrupted，保留快照及已有候选，不自动重发模型请求。关闭候选窗不等于丢弃。

## 接受与恢复

宿主核验书章存在及请求基线，冻结作者编辑缓冲。接受候选前比较当前书章 ID、完整缓冲及范围，仍由编辑器执行一次可撤销事务；先保留当前稿快照，保存成功后记录新正文 hash 和接受事件。旧任务或不匹配缓冲只能查看/复制候选，不能静默覆盖。用户之后撤销属于新的稿件变化，不抹掉历史接受记录。

任务页支持查看、打开对应章节、审阅、取消和显式丢弃；失败原因分类但不显示供应商原始响应或凭据。费用显示供应商用量与未知字段，未配置价格时不伪造金额。候选与任务数据始终在私有应用目录，不进入 GitHub。

## 验收

真实官方 Harness + 本机 fixture 验证：生成候选后重启仍可查看；中断任务不自动重跑；任务作用于准确书章；正文外改/继续编辑拒绝旧接受；取消关闭子进程且正文不变；两次并发请求只运行一个；接受与一次撤销保持字节准确。实际云供应商、文学质量和费用准确性分别列出证据，不由 fixture 推断。
