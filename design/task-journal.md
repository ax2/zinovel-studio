# Stage-003 任务与候选恢复设计

状态：日志、官方 runtime、宿主目标绑定、任务界面及接受回执恢复已接入；2026-10-23 增加跨书/旧版记录分页、取消后提案及流式片段保留、显式重试。用量和预算仍待完善。

## 问题

原实现缺少书/章/选区基线、恢复入口与原子状态，并发占位也晚于异步准备；下述实现逐步修复这些问题。

## 文件与状态

继续使用应用私有 tasks/<UUID>/ 目录；task.json 是有 schemaVersion 的轻量索引，snapshot.json 保存冻结的书/章 ID、完整编辑缓冲、存盘基线 hash、UTF-16 范围、技能版本和上下文来源，proposal.json 保存候选。用同目录原子写入，路径拒绝链接和越界；列表不加载全部正文。

准备阶段立即占用单任务槽位。状态为 preparing → running → awaiting-review → accepting → applied；旁支包括 acceptance-uncertain/cancelled/failed/interrupted/discarded。启动时把遗留 preparing/running 标 interrupted，保留快照及已有候选，不自动重发模型请求。关闭候选窗不等于丢弃。

恢复只在桌面取得官方单实例锁之后初始化一次；构造运行时本身不读写任务，避免第二次启动改动第一实例的运行状态。正常退出取消时等待任务落盘完成。技能、输入、候选与状态原子保存；工具读取只返回 context/selectedText，不暴露任务内部元数据。

## 接受与恢复

宿主核验书章存在及请求基线，冻结作者编辑缓冲。接受前编辑器比较当前书章、完整缓冲及范围并先保存原稿；宿主再次校验真实正文，写入 accepting 意图，然后通过同一个存储事务保存正文、book.json 及 .zinovel/task-receipts/<intent UUID>.json，最后将 task.json 标为 applied。编辑器显示已保存正文，仍保留一次撤销。旧任务或不匹配缓冲不能静默覆盖。用户之后撤销属于新的稿件变化，不抹掉历史接受记录。

重启先恢复书内已有 pending 事务，再读取接受回执。匹配的回执证明接受发生过，即使作者后来改稿也可修复任务状态，绝不把当前正文改回候选。没有回执且原稿仍在，回到 awaiting-review 并保留作者确认文本；正文不同、回执不匹配或目标不可读时标 acceptance-uncertain，供人工核对。只看正文等于候选不能证明接受事件。正常关闭等待接受事务完成；任务回执写入失败时仍显示已保存的正文，并提示待核对。

任务页支持查看、打开对应章节、审阅、取消和显式丢弃；失败原因分类但不显示供应商原始响应或凭据。费用显示供应商用量与未知字段，未配置价格时不伪造金额。候选与任务数据始终在私有应用目录，不进入 GitHub。

## 验收

当前界面提供全局任务入口、当前书/全部作品/未绑定旧任务范围，每页 100 条，可继续翻页。详情有原要求/选区/候选、对应书章跳转、继续审阅、标记放弃。旧版无绑定记录只读展示，不猜测章节，不直接应用。

取消、失败及中断后的有效 proposal.json 可保留为部分结果；原先没有候选字段的旧记录也能只读显示已落盘提案。部分结果不可直接接受。作者在对应章节点击“用当前选区重试”会创建带 retryOf 的新任务，重新冻结当前编辑缓冲和范围，保留旧任务和原要求。宿主拒绝跨章节重试；无自动重发或写章。

官方 SDK 0.2.1-rc.2 只转发持久 session.event，不转发逐字片段。因此小说插件使用官方 agent/assistant-stream 事件，只捕获主会话 text-delta；排除推理、工具参数和原始协议对象。stream.json 采用原子替换，200ms 合并写入，慢磁盘期间只保留最新内存状态，不排队完整快照。正常结束/插件释放会等待落盘；强杀只能保证最后成功写入的版本，不能保证最后 200ms 或 I/O 尚未完成的片段。最多保留 32 次尝试、合计 120,000 UTF-16 单元，截断有标识且不切断边界上的代理对。

恢复优先有效提案，否则展示 stream.json 中已落盘可见文字，标记 partialSource=stream；可能含说明文字和多次尝试，不视为完整候选。任务中断不会执行其中指令或自动改稿。断电、磁盘满及慢盘具体延迟还需专项验证。

已覆盖接受意图前后、正文事务完成但任务回执未完成、外改与混合落盘状态；接受恢复不启动模型或重新执行写稿。OPS-04 的当前 schema 与 alpha.1 旧记录恢复行为已验证；不扩大为任意未来版本迁移、磁盘损坏、物理断电及低配置设备已验收。

真实官方 Harness + 本机 fixture 验证：生成候选后重启仍可查看；中断任务不自动重跑；任务作用于准确书章；正文外改/继续编辑拒绝旧接受；取消关闭子进程且正文不变；两次并发请求只运行一个；接受与一次撤销保持字节准确。实际云供应商、文学质量和费用准确性分别列出证据，不由 fixture 推断。
