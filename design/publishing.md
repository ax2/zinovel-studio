# 导出与发布

## 分层能力

| 层 | 产物 | 首次阶段 |
| --- | --- | --- |
| 文本导出 | 按选择章节合订 TXT / Markdown；编码与目录可选 | Stage-002 |
| 阅读制品 | EPUB 3、DOCX、PDF、独立 HTML 书站，封面目录图片 | Stage-007 |
| 可配置站点 | 静态目录、Git 驱动站点、SFTP、ZiCode 适配器 | Stage-007，逐适配器资格验证 |
| 投稿辅助 | 平台排版、章节复制、封面/简介/标签/投稿包 | Stage-007 |
| 定时连载 | 按排期发布已确认快照，失败回执、去重、重启恢复 | Stage-008 |

平台支持状态分 planned / configured / verified / unavailable。未实现/无官方 API 的目标不显示“发布成功”。内容平台的规则与接口要在实际集成时重新核实。

## 发布状态机

draft → prepared → previewed → authorized → uploading → verified。异常进入 failed 或 unknown，远端已收到但客户端超时不能直接当失败重发。独立的 exported、remote-draft、published、delivered 状态分别保存。

prepared 冻结 snapshotId、目标、章节 ID/顺序/hash、资源 hash、书目与版权信息、发布范围。授权绑定此快照和目标；正文后续改动不悄悄进入已授权任务。发布只读取快照，不边写边发。

上传前检查目标目录、差异、引用、编码、资源与缺章；默认增量上传，不清空目标。可原子切换的目标先上传到 staging 再切换 manifest；不能原子切换的目标说明半发布风险，保存上传清单与恢复入口。初次目标验证使用试验目录，不触碰已有书。

幂等键由目标 ID + snapshotId 派生，重试前查询回执和远端内容。验证比较章节/资源清单、首尾内容、链接、HTTP 状态与 hash（目标支持时）；接口返回 200 不是完整阅读体验验收。回滚只能回到已知旧快照，不能顺带删除他书文件。

## 各格式验收

- TXT/MD：章序、标题、缺重章、净字数差异、首尾段与编码。
- EPUB：目录导航、封面、资源引用、元数据、中文段落，EPUBCheck 和至少一种真实阅读器；检查通过不等于所有设备一致。
- DOCX：标题层级、分页、段落、图片、注释配置，真实打开；不要求 Word 宏。
- PDF：字体与字形、换页、目录、超长段、图片分辨率，渲染抽查首/中/末页，不只看文件存在。
- HTML：桌面/手机、上一章下一章、目录、夜间、图片加载、长题名、无剧透作者备注边界。

## 小说版权和应用开源

程序开源不等于小说开源。私有作品不上传 ax2/zinovel-studio。模板与演示只用新写合成内容。封面/图像记录来源与使用范围；作者署名、AI 辅助说明、平台声明由作者配置。发布检查提示缺失项，不做未经证实的法律结论。

ZiCode 适配器从现有 `books/<slug>/manuscript`、`worldbuilding`、`outline` 和 `production` 读取映射，但不复制个人部署脚本或密码。同步站点、上传草稿、正式公开和私有备份是四个独立动作。
