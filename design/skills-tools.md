# 技能、工具、上下文和任务

## 分工

技能是创作方法；工具是可验证的有界操作；工作流组合任务与检查点；模型只负责生成/判断候选。权限、持久化和发布授权由宿主实施，不能写在提示词里就假设安全。

首批技能在 [catalog](../skills/catalog.json) 中，全部 authored-not-integrated。后续可选技能：风格画像、术语校对、翻译对齐、朗读校读、系列管理、读者反馈。具体接入先以 Stage-003 的读稿→局部提案→接受闭环验证。

工具完整目录见 [tool-catalog](../contracts/tool-catalog.json)。这是设计契约，字段列表尚不是可执行 DSH Schema；Stage-001/003 读取固定版本 SDK 再实现类型、注册、错误与事件。不得把设计名当成已经存在的工具调用。

## 公共请求/响应契约

请求携带 requestId、bookId、taskId、基线版本及 capability scope。响应统一含 status(ok/conflict/partial/failed/unknown)、result、sourceRefs、warnings、error(code/retryable) 和 duration。读正文标明 requested/read/truncated 范围；结果太大要分页或 spill，不静默裁掉正文又说读完。

正文和实体变更工具仅生成 proposal。apply/accept 是编辑器领域 API，在核对基线与用户授权后提交；不对一般写作 Agent 暴露任意写盘。高自治工作流也必须预先选择可写草稿范围/预算/停止条件，正式稿与公开发布是独立能力。

## 技能路由与分层加载

根据用户动作、工作区实体和请求选择技能；在技能目录只加载 name/description，执行时加载正文，只有需要时再查设定与材料。润色不同时塞入整套建世界和发布技能。作者可查看和覆盖本书风格规则，技能升级保留版本号及差异，不能静默改变正在进行的书。

一个技能包记录 id/version/来源/支持语言/所需工具/输入类型/产物类型。导入自定义 SKILL.md 先预览，不执行附带脚本；脚本与网络能力按宿主能力单独启用。无公共插件市场，后续提供本地技能导入即可。

## 上下文构建顺序

硬约束：当前选区及邻接段 → 当前场景与目标 → 生效正典与角色认知 → 相关主支线/伏笔 → 最近实际正文与摘要 → 作者风格 → 相关资料。先按书 ID、时间、角色和主题筛选，再作文本检索；可选 embedding 不能覆盖结构过滤。

context manifest 包含来源 ID/版本/hash、用途、预算和裁剪说明；预算不足先减弱相关材料，不能截掉锁定事实后仍声称遵守。历史章节回看有成本控制。盲读模式首遍禁止把总纲答案送给审读者，第二遍核查再补充。

## 方法来源的适配

保留本地技能的阅读承诺、人物动机、因果、正文证据、独立读感与复读、交付状态区分。固定对白比例、章长、伏笔频率、特殊引号规范与旧站点绝对路径不作为全局规则；由作者按书选择。计数/重复/编码由确定性工具处理，文学判断保留具体证据和不确定性。

## 注册与验证门槛

技能文件可解析 → 宿主发现 → 路由正确 → 工具真实注册 → 参数校验 → 模型真实调用 → 结果返回 → UI 提案 → 正文接受/撤销 → 版本/日志核验。逐层记录，不把第一步冒称整套内置完成。

每个技能至少有正常输入、缺失资料、用户手改冲突的行为样本；发布/图像还测供应商未配置与未知结果。单元测试、fake provider 和真实模型验证分别标注，真实调用前遵守用户已配置的费用/网络范围。
