# Stage-003 用量与预算

2026-10-23，第一切片。OPS-02 仍进行中：已实现供应商用量、模型步骤/输出/章节上下文限制；金额估算、价格配置及完整输入 Token 预算尚未实现，不把费用未知显示成零。

## 每任务冻结

模型设置保存 maxSteps（默认 12，1–64）、maxContextCharacters（默认 120000，100–120000）、maxOutputTokens（默认 8192，64–32768）、maxReportedTokens（默认 0 为未启用，上限 1000000）。旧设置自动使用默认值。每个任务持久保存独立 budget；修改全局设置只影响新任务/明确重试的新任务。章节字符采用编辑器 UTF-16 长度，在任何供应商请求前拒绝超出部分，不静默截断正文。

官方 agent/request hook 在下一步准入前检查步骤数与已回报用量；达到阈值先保存 stopReason 再抛出停止信号。输出上限传入官方 SDK 与每步配置。步骤数不等于供应商内部网络重试次数，也不表示完整任务费用封顶。正在进行的单次调用可能跨过已回报 Token 上限，之后的步骤才会停止。

启用已回报上限且先前步骤/尝试未给出有效用量时，下一步保守停止为 usage-unknown。实际 DeepSeek 适配器对缺少用量的 fixture 响应在更早位置失败，真实测试记录为适配器失败；usage-unknown 的下一步策略由单元测试覆盖，不伪称该 fixture 走到了预算 hook。

## 用量来源与恢复

小说插件通过官方 agent/assistant-stream 捕获 usage；按 attemptId 保存最后一次合法计数。重复回报替换旧计数，不重复累加。未知字段不补零。inputTokens 为非缓存输入，cacheReadTokens/cacheWriteTokens 单列；reasoningTokens 为输出分项，totalTokens 为替代汇总，两者均不叠加进输入/输出总数。

usage.json 原子写入，记录每步准入、至多 256 个尝试、有效供应商字段和停止原因。重启时 TaskJournal 有界读取并生成摘要，不执行模型。准备前拒绝不会创建模型调用；超过预算的任务保持 failed/budget-limit，已有提案或流式结果只读。作者修改设置并明确重试后创建新任务，旧输入、结果、预算保持可查。

界面区分已回报合计、未知尝试、未知缓存项和费用未知。已回报合计仅含可确认字段，不能当作服务商账单。纯隐藏的网络重试、供应商未回报消耗、崩溃前未写入用量可能无法精确归账。
