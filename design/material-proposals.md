# 结构化资料 AI 提案

2026-10-23 实施决策：优先完成现有八类资料的 Agent 提案与审阅闭环。新的资料先手工命名保存，然后对该卡生成候选；不将正文任务伪装成资料任务，不允许 AI 工具直接写书目录。

宿主读取并冻结准确 book ID、资料 ID、kind、revision、文件 hash 及字段。模型只能提出 title/fields/notes；类型、章节关联、作者确认状态和 evidence 由宿主保留。候选经过类型字段校验，再独立保存到任务目录。文风/创意/人物/大纲方法继续来自内置技能源；读取授权限制为任务冻结内容与作者明确选择的资料。

作者在语义表单中对照旧值、调整并接受。接受前核对冻结基线，任务先写接受意图，书内同一个事务更新资料、旧版本历史和接受回执，再完成任务状态。恢复只对账，不重新调用模型或重写资料；接受之后的作者修改不能被恢复覆盖。正文接受协调器和资料协调器按任务类型分别处理。

验证门槛：字段越权/同版本外部改动拒绝；真实官方 Harness 工具回合；模型候选不改正式资料；作者调整保存、重启恢复、明确接受；跨书隔离；意图前后和事务/回执各崩溃点恢复；安装后最终复测。尚未完成这些验证前，不宣称资料 AI 可用或发布新版。

## 已实现的开发切片

官方 SDK 复用同一个运行槽和预算管线；资料任务记录 kind=material 和准确 materialTarget，不伪造章节绑定。注册 novel_material_read / novel_material_propose，有显式参考时另注册 novel_materials_read。字段提案最多 12 万字符，宿主再次校验后存入任务，模型不能改资料原文件。

书内 `.zinovel/material-acceptance/<id>.json` 与新资料/旧版历史在同一恢复事务内写入。MaterialTaskAcceptance 与正文协调器互不解释对方的任务；启动和关闭都覆盖两个协调器。审阅草稿继续使用现有版本与接受身份规则，空标题草稿可恢复，但接受必须有效；已应用任务展示作者最终接受内容。

已通过单元检查和真实 Electron/官方 SDK fixture：候选独立、无权限字段拒绝、作者调整重启恢复、外部修改拦截、两个实际进程退出点与桌面启动对账。增加了部分书内事务回放测试。浅深主题与窄窗可滚动审阅已检查。真实云模型文学质量、全部八种资料的生成质量和本版本安装包尚未验证。
