# 开篇试写与文风实验（后续切片设计，尚未实现）

对应 IDEA-02/03/04/05/08。现有 novel-pilot 方法要求同一具体场景比较声音、保留实验分支，不把所有候选混成正式首章；当前工具还没有专用分支，不能将方法已接入当作该功能完成。

## 数据边界

采用书内独立试写文档，正文仍为 UTF-8 Markdown。拟定 pilots/<id>.md 与 pilots/<id>.json（身份、revision、正文 hash、实验组、视角、声音、目标读者承诺、父分支版本、作者选择与理由）。不把长正文塞进资料笔记字段，也不创建隐形作品或伪造正式章节 ID。

实验组固定同一场景任务，关联创意/人物/场景资料时保存 ID 与当时版本/hash。手工复制分支冻结来源版本，之后互不联动。删除为软删除；版本历史与全部已保存分支进入整书备份。作者选择哪个版本是一条显式决定，含选择时的版本/hash，后续修改会提示选择已过时。

## 写作与 AI

试写编辑器复用 CodeMirror，提供直接手改、未保存草稿保护、撤销与版本冲突。正文保存、元数据与历史必须在已有 BookStorageKernel 的同一事务内；不得复制一套不受约束的文件写入路径。

Agent 任务绑定 trial 文档身份，独立试写读/提案工具，只能读冻结正文和作者明确选定的资料。不能用 chapterId 偷换试写 ID，也不能让旧正文接受协调器解释试写任务。需要在现有接受恢复协议上明确目标适配层，保留旧章任务兼容测试；候选由作者接受，关闭、取消、重启均不重放模型。

并排比较显示样稿、叙事视角、声音、主角行动、阻碍和读者承诺，以及哪些来源版本已经变动。定量字数只作辅助，不自动给文学质量定分。反馈记录必须绑定试写版本及来源，不能用新稿覆盖旧反馈对象。

## 进入正式写作

明确“建立新章节”才从选定试写生成一个新稳定章节 ID，事务同时写章目录、正文和来源回执；默认不覆盖既有首章。移动到第一章由现有章节排序操作完成。若之后提供替换现有章，必须走已有版本检查、差异审阅与恢复规则，不能自动替换。

## 必须验证

多份分支互不覆盖；同场景不同声音可手改和比较；选择决定绑定旧版本并能识别后续变更；外部修改与 Unicode/长文往返；真实关闭/重启恢复未保存调整；接受前后实际退出恢复；正文新章导入后原首章字节保持；整书备份恢复分支、来源与选择记录；窄窗比较可访问。先完成这些行为再给 IDEA 条目验收，不使用静态卡片证明创作闭环。
