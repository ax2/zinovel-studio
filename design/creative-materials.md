# 创作资料：手工闭环与存储约束

2026-10-23 第一切片覆盖八种类型：创意、人物、地点、世界规则、纲要、场景、主支线、伏笔计划。每种类型提供有语义的字段和可选项，笔记保留原始 Unicode/换行。当前是资料管理；关系图、时间切片、认知矩阵、正文证据与地图不在此切片中。

## 主数据与身份

资料位于 `materials/<UUID>.json`，schemaVersion=1；包含 kind/title/status/fields/notes/chapterIds、revision 和时间。只支持作者计划 planned 与作者已确认 accepted，不提供 established 状态，因此不能把尚未写进正文的设定当成正典。

章节引用只保存书内稳定 ID，无冗余 bookId。章节改名不破坏引用；删除或缺失显示异常。新关联必须属于当前书且未删除，已有失效引用保留以便人工核对。人物改名与别名更改不进行正文替换。伏笔卡的埋设/强化/回收都是计划文本，后续需独立证据事件。

## 同一写入队列和事务

BookStorageKernel 从已有 NovelStore 提炼路径拒绝链接、单实例串行队列、恢复日志、manifest 和多文件事务。NovelStore 与 MaterialStore 共享一个实例；资料服务不新建队列。原有正文/备份/结构操作也走同一个内核。

资料保存同时核对 revision 和原文件字节 SHA-256，外部编辑即使不增加版本也会冲突。写入前保留旧完整 JSON 至 `.zinovel/material-history/<id>/<revision>-<sha256>.json`，经共享事务更新资料与历史；中断由相同恢复协议处理。删除只添加 deletedAt，恢复保留同一 UUID。历史最多显示最近 40 项，载入旧版只改变编辑缓冲，明确保存后形成新版本。

损坏资料不覆盖，列表逐项报告无法读取，其他资料仍可打开；损坏版本的保存失败。链接路径拒绝访问。旧版程序能忽略资料文件，但旧版不能管理它们；不是已验证的降级兼容承诺。

## 界面与暂存

正文旁“创作参考 → 资料卡”可筛选、搜索标题/别名/字段、每页查看 40 项。保存按钮明确持久化，选择其他卡或关闭窗口前的输入同步写入本机 localStorage 草稿；重新打开相同卡可找回。草稿保留最初版本与 hash，不能绕过冲突检查。清空新建草稿、重新读取放弃调整均为明确按钮。

未保存的本机草稿不属于整书备份，不能冒称已保存。草稿暂存失败会提示保留窗口并保存。书目录备份包含已保存资料、历史、章节引用；恢复分配新 book ID，书内资料/章节 ID 保持，旧书不变。全局 AI 任务与审阅草稿仍另存于应用 tasks/，尚未纳入整书备份。

导出只读取已保存版本，经原生保存对话框输出 Markdown，包括类型、状态、版本、字段和章节 ID。导出不是小说发布，不调用云模型。

## 验证边界

存储测试：八种实体往返、正文/资料并发、过期写入、外部同版本编辑、事务重放、目录链接、损坏保留、软删除、历史、跨书隔离、备份恢复。真实 UI 流程与截图记录于 Stage-004 工作日志及 screenshots/stage-004/materials。

尚未完成：结构化实体之间的关系、资料变更提案工具、场景看板、大纲影响分析、真实模型文学质量、完整工作区迁移。不能仅凭八种表单将 Stage-004 或全部对应功能标 verified。

## 正文证据增量

资料可绑定正文事实、伏笔埋设/强化/回收、人物状态、关系和认知事件。每条证据有独立 ID、正文选区锚点、原始引文/hash、故事时间、知情范围、关联资料 ID 和 active/retired 状态。只能使用当前作品已保存的非空正文，宿主核对全文、hash 和 Unicode 边界，不以界面选区代替验证。字段保存不会接受调用方伪造的 evidence 数组或覆盖已有证据。

读取时解析原始锚点；章节版本变化统一标 stale，即使引文可唯一重定位也需作者复核，多个匹配不猜位置。当前章保存后界面自动刷新状态；外部修改、其他章节变化可通过“重新检查证据”读取。重新确认必须明确选择新范围，原证据进入资料历史；停用保留记录。关联对象改名解析最新标题，删除/损坏显示异常。对象字段变化的依赖传播、全书总览及段落跳转尚待补充。

历史界面可查看旧证据，但“载入历史为草稿”只恢复资料字段与笔记；证据需单独复核或停用，不能借旧版字段覆盖后来的关系/伏笔记录。资料导出包含证据、来源和当前检查状态。
